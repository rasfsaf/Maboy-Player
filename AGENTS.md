# Maboy Player Project Rules & Directives

## 1. Drag-and-Drop Everywhere for Tracks (Обязательное правило)
Везде в интерфейсе приложения Maboy Player, где отображаются списки треков (Главная библиотека, детали плейлистов, очередь воспроизведения в плеере `PlayerSheet`, синхронизированная очередь устройств и любые другие списки треков), треки **всегда и без исключений** должны поддерживать перемещение drag-and-drop:
1. **Reorderable-компоненты:** Использовать `ReorderableListView.builder` или `SliverReorderableList` с фирменным стилем перетаскивания `proxyDecorator: maboyReorderProxyDecorator`.
2. **Защита от дерганий анимации:** Обязательно вызывать `controller.beginReorder()` в `onReorderStart` и `controller.endReorder()` в `onReorderEnd`. Это замораживает фоновые обновления списка во время анимации перемещения.
3. **Мгновенный захват мышью и тачем (Drag Handle):** Каждый элемент списка треков должен содержать явный визуальный манипулятор захвата (иконка `Icons.drag_indicator` с курсором `SystemMouseCursors.grab`), обёрнутый в `ReorderableDragStartListener`. Это позволяет пользователям на ПК и мобильных устройствах сразу захватывать и перемещать трек без 500-мс задержки `delayed`.
4. **Сохранение кликабельности:** Обычный клик/тап по треку запускает воспроизведение (`onTap`), а захват за манипулятор `Icons.drag_indicator` (или долгое удержание строки через `ReorderableDelayedDragStartListener`) осуществляет перетаскивание.

## 2. AppController не раздувать
`client/lib/src/app_controller.dart` уже перегружен (библиотека, плеер, синхронизация, UI-состояние). Новую логику туда не добавлять.

1. Новый сценарий (друзья, эквалайзер, загрузки, сеть) оформлять отдельным сервисом в `client/lib/src/services/` и подключать его из контроллера тонким вызовом.
2. В `AppController` допустимы только оркестрация и состояние, которое реально нужно нескольким экранам. Разбор payload, валидация и хранение — в сервисе.
3. Если правка контроллера не умещается в небольшой метод, сначала вынести существующий кусок, потом менять поведение. Не лечить рост файла ещё одним блоком на сотни строк.

## 3. Обязательный Git Commit перед завершением задачи
Перед завершением любой задачи, передачей ответа пользователю или окончанием итерации:
1. Обязательно выполнить проверку `git status`.
2. Добавить новые и изменённые файлы в индекс (`git add`).
3. Зафиксировать изменения осмысленным коммитом (`git commit -m "..."`).
4. Ни при каких обстоятельствах не оставлять рабочие файлы незакоммиченными, чтобы исключить любую потерю данных при сбросах или переключениях.

## 4. Безопасность файловой системы (Запрет масок в корне)
Никаких `Remove-Item` или `rm` по маскам в корне проекта и в рабочих директориях. Удаление любых временных данных допускается исключительно точечно с явным указанием одного конкретного пути.
